## 6. Hazards, encoding decisions (T0) and open questions

T0 decisions (encoding; no manuscript change needed):
- **Simple = rank injectivity.** `Q_l : FGraph` is simple by type (a `Finset` of non-diagonal
  `Sym2`), so "no parallel edges" would be vacuous if stated on `Q_l` alone. The Spec states the
  substantive content: distinct layer edges give distinct `Q_l`-edges (otherwise the `Finset` would
  silently merge them and an item would disappear from `Q_l`), plus `w₁ ≠ w₂`, `h ∈ D_l`, `w ∈ Pool_l`,
  `h ≠ w`, the sub-layer tags (one sub-layer per edge, `ι ≥ 1`, `κ < 3M` / `κ < 4M`, bipartite HUB
  edges) and no isolated vertices.
- **"succeeds / always finds / is well defined" = no fallback.** The construction is total
  (quot.md D-Q-6), so WellDef (i), (iv), (v) add the no-fallback conclusions: every PAR object gets a
  colour `< 3M`, every (e1) item gets a junction in `Cand(u)`, every end of `E'(u)` gets an (e2)
  junction in `Cand(u) \ Used(u)`.
- **Lift (iii), "exactly one lent class".** The round step reads only the classes `LJV_{Y,l}` of the
  ancestors of the past, so uniqueness is stated among them (`∀ Y ∈ I.ancs, uw ∈ LJV_{Y,l} →
  Y = Y(u)`). Exclusivity against the other lent classes (`Own`, `LJS`, `LU`, other rounds) is a
  property of `StageData.ofOutcome` (one COL label per edge, s3:defCOL) and "the only consumer of
  this class is the round-`l` step" is a property of the whole assembly (COL(g), s6:lemLent;
  blueprint LIFT-COLG-META). Neither is formalized here; neither is used by (iv).
- **Lift (iii), "lies in an edge of `Q_l`"** is `ItemInQEdge` (a J-edge of a layer edge whose
  rank-sub-layer `Q`-edge is `q`), independent of the choice function `layerOf`. The statement uses
  the exclusive form "paid and in no `Q`-edge, or unpaid and in exactly one" (the TeX's "either …
  or"; exclusivity is what (iv) needs).
- **Lift (ii), "pairwise edge-disjoint objects"** is `Nodup` of all edges of all lifted objects (it
  includes "the lifts of distinct members are pairwise edge-disjoint").
- **Run-level corollaries** (`MultRunStatement`, `LiftJConsumerRunStatement`) take
  `(RoundInput.ofPast run G δ S π l J).Valid` instead of the run hypotheses (RunHyp, coherent stage
  data, designation). **They are conditional on `ofPast_valid`** (open obligation OBL-P1-1, §3):
  the hypothesis bundles s6:lemJplus, s7:lemCand (iv) and s2:propStructure (iii), and no Spec states
  its discharge yet. Only modulo `ofPast_valid` do they imply the TeX's run-level claims (then they
  are at least as strong, since they need no further run hypothesis); on their own they are weaker
  than the TeX. Their hypotheses are not shown satisfiable for `3 ≤ l ≤ R` (H4). They are the exact
  shape needed to build the `EG.Chain.JConsumer` instance once `ofPast_valid` is available. The
  docstrings of both statements say this (fix round 1).
- **Classical filter** in `WellDefParStatement` (`ParObj.Conflict` has no `Decidable` instance).
  Since fix round 1 the `open Classical in` is scoped to the filter of conjunct (1) only; conjuncts
  (3), (4) elaborate with the same instances as `LiftRolesStatement` (checked in
  `EGTest/ProbeP1.lean` with `with_reducible exact`). Proofs of conjunct (1) must use the classical
  instance, or `Finset.filter_congr_decidable`.

Hazards:
- **H1 (refutation target, Lift (ii)).** A lifted cycle repeating a vertex is excluded by six facts;
  each is available in the Lean encoding: (1) copies of one sub-layer with distinct tags-and-vertex
  are distinct vertices of `G` (tag equality inside a sub-layer); (2) ports of distinct same-colour
  PAR objects / hub items are distinct (proper greedy colouring, `Rules.Valid.parOrder`; injective
  SDR, `Rules.Valid.sdr`); (3) `p_i ≠ q_i` (`Quot.out` of a non-diagonal `J^par` edge; `Nodup`
  pairing list for cherries, `Rules.Valid.pairing`); (4) middles of same-colour cherries distinct
  (WellDef (i)); (5) hubs, fresh centres, ports pairwise disjoint (`I.Valid.roles`); (6) live vs
  pooled (`not_mem_pool_of_mem_live`). I re-derived the argument for the Lean definitions
  (`liftObj`, `interior`, `layerOf`) and found no counterexample: the lift of a cycle
  `[w_0][w_1]…` entered at `w_i` produces `w_i p_i (x_i) q_i`, and `h_i u_i`, `w_i u'_i` for HUB
  cycles, from any start and direction. Status: **not refuted, not yet proved** (stage 2).
- **H2 (MULT-J1).** MULT rests on (J1) aggregated over all parts of round `l`; `RoundInput.Valid.J1`
  has that form (filter over all of `J^hub`), which `JPlusProps.J1hub` exports. A per-part J1 would
  make `MultStatement` unprovable. Probe P-2 must hit this target on the s6 side.
- **H3 (rank injectivity uses the list order).** `Rules.rank` counts earlier entries of
  `rankOrder` with the same rank-0 `Q`-edge; injectivity needs `rankOrder` `Nodup` and enumerating the
  layer edges (`Rules.Valid.rankOrder`). Ranks are exactly `1…m` on each (layer, pair) class even for
  edges without a `Q`-edge (their rank-0 `qEdge` is `none`, a separate class), so the MULT sub-layer
  identities need no WellDef.
- **H4 (run-level non-vacuity not checked).** The run-level hypotheses need a valid run with
  `R ≥ 3`; the only valid run of the tests (`EGTest.HB.run1`) has `R = 1`. The round-level
  hypotheses are checked on `EGTest.Quot.Live.I` (§7).
- **H5 (Cuckoo, fixed rules).** (iii) is true only because `Rules.group` (and ultra status) read the
  past only (patch set R, TRIAGE §1a): the argument types of `Rules` enforce it (no `Lists` argument).
- **H6 (junk values).** `etaAt`/`zetaAt` are junk off `V(G)`; hub items have both ends in `V(G)`
  (`J_sub` + `edge_verts`), so the lists read are the real ones. `inOrder` drops candidates outside
  `V(G)`; `Cand ⊆ Pool_l ⊆ V(G)` (`pool_sub`).
