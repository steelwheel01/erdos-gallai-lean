## 2. Cross-cutting decisions proposed for the integrator

- **Deterministic Specs (TPV-DET-SPEC, PV-DET-SPEC, VX-DET-SPEC; decision needed before the s5-s7 Specs are locked).** Each of the three statements has the shape 'there is an event G of probability >= 1/2 - eta (resp. 1 - eta) such that on G, for EVERY admissible edge set, a decomposition with properties X exists', where X does not mention the labels. Since eta <= 1/100, G is non-empty, so the statement is equivalent to 'for every admissible edge set, a decomposition with X exists'; conversely the ∃G form follows from that with G := the whole space, so an ∃G Spec has no additional content and would mislead reviewers. The consumers use only non-emptiness (s7:lemOneOutcome: 'only this non-emptiness is used'; s5:lemChild, s5:lemDemoted: '>= 1/3'). Proposal: lock `TPVStatement`, `PVStatement`, `VXStatement` in deterministic form; keep the explicit good events and their probability bounds as Lib lemmas (`tpv_prob_good`, `pv_prob_good`, `vx_prob_good`) used only inside the proofs; tell the s5, s6 and s7 blueprints that the stage-3 labels of TPV/PV/VX+ need not be modelled (s5:lemChild, s5:lemDemoted, s6:consOrder, s7:defSchedule and s7:lemOneOutcome become deterministic applications; the 'deterministic procedure' meta-claims are realised by `Classical.choose` on the ∀E∃ statements).
- **Size predicates and N0 (TPV-SIZE-PRED).** New protected file `EG/Defs/Vortex.lean` with `etaTPV`, `etaPV`, `etaVX`, `TPVSize`, `PVSize`, `VXSize` (conditions (i) L >= 2^10, (ii) N >= L^3, (iv) eta <= 1/100; (iii) 4 beta <= L follows from (i)) and `pvJ`, `pvM`, `pvB`. The Specs take `TPVSize (O.card : ℝ)` etc. instead of `N >= N0`; s1:defConstants' `N0Cond` (s1 blueprint) is defined after them and must use the same names (the s1 blueprint wrote `EG.S4.TPVSize`; unify to one namespace). A Lib lemma `∀ᶠ N in atTop, TPVSize N ∧ PVSize N ∧ VXSize N` gives N0. Remark: every size condition actually follows from L >= 2^10 alone, so N0 = 2^1024 would work, but proving eta(2^1024) <= 1/100 numerically is not worth it.
- **One vortex engine (TPV-ENGINE-SIZE, PV-SIMILARLY).** Modules: `EG/Lib/Vortex/Trail.lean` (trails, rep, (S) splitting into <= rep cycles + <= 1 path with the same ends; (C) closing), `EG/Lib/Vortex/Ends.lean` ((E): parity of path ends and |P| <= |W|; may live with Cor 22), `EG/Lib/Vortex/MonoComp.lean` ((MC) for `indepSubset` vs `rsubset`; (B) via `chernoffGen_lower_half`), `EG/Lib/Vortex/Labels.lean` (colour types, truncated level law, kappa laws, product label spaces, run sets, their laws), `EG/Lib/Vortex/Step.lean` (a generic step: given W, U+, classes with avoidance sets V_c ⊆ U+, reserved edge pairs per (w,c), a Corollary-22 decomposition per class, a path-connectivity certificate for each R_c through V_c with multiplicity t >= 2 + b, and an arc selector, produce objects (cycles/single edges) and arcs, pairwise edge-disjoint, covering F plus the connector edges, with the cost bound), then `TPV.lean`, `PV.lean`, `VX.lean`. Specs in `EG/Spec/Vortex/{TPV,PV,VX}.lean`, proofs in `EG/Proof/Vortex/`.
- **Label encodings (Lib only once the Specs are deterministic).** Colours `Option (Fin J × Fin 3)` (none = M) with a transport lemma to `randColouring (Fin (3J+1))` for L15+; levels `Fin (J+1)` with the truncated law; kappa `Fin 4` / `Fin 5` with class c ↔ kappa = c.succ; PV phases `Fin 4`, ext `V → Option (Fin 4)`.
- **New Defs needed by the PV/VX Specs from other chunks.** `EG.IsPathDecomp`, `EG.pathEndCount` (s1 blueprint, s1:citCor22) and `EG.Obj.isEdge` (currently Lib, `EG/Lib/Found/Fnum.lean`; s1 blueprint EG0-ISEDGE) must be moved/added to `EG/Defs/**` before PVStatement and VXStatement are locked.
- **PV own classes (PV-OWNCLASS-INDEX).** Index type `Fin (pvJ N) × Fin 4`; s3:defCOL must use the same `pvJ` (J_Z = floor(log2(L_Z/8))) so that s5:lemChild can pass the colour classes without casts; s3:defCOL/lemCOL must deliver spanning, (2^-6, s')-expanding, pairwise edge-disjoint classes including M.
- **Stage-alpha.** The proofs use Cor 22 (from Lovász) and T16* (whose proof uses Haxell); Specs stay hypothesis-free, proof theorems take the hypotheses.
- **Undeclared dependencies found in proofs** (for usesgen/msreport): all three use s1:citDef7, s1:citDef11, s1:defObject. **Declared but not logically used:** s1:condG3 (all three), s3:lemHB (PV: A(w) are given data), s4:lemTPV (PV: proof text reuse only). s1:citMarkov is correctly absent from VX+.
- **Hierarchy data.** None of the five nodes refers to the hierarchy (runs, rounds, pre-parts, pieces, parts, ancestors, designations, pools, zones, clusters, quotients). The instantiations live in the consumers: TPV in s6:consOrder step (1) (Z^0, O_Z, Ret_Z, Qs_Z, Erem(Z)); PV in s5:lemChild (light part Z, X_Z, Aw_Z, own classes of s3:defCOL(iii), Rt(Z), Pl(Z), ext from round-l zones); VX+ in s5:lemDemoted (demoted light part Y, X_Y, E between E(X_Y) and E_r(Y)).
