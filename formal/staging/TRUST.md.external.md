# Proposed TRUST.md additions — out-of-band acceptance criterion (agent id: `external`)

Status: PROPOSAL for the integrator/user. `TRUST.md` is edit-denied for agents, so this file states
exactly the additions the out-of-band checks (`scripts/FinalCheck.lean`, `scripts/Statement.lean` /
`STATEMENT.md`) need. It is scoped to those checks; the tooling agent proposes the `check_pins.sh` /
lint / CI additions, and the bridge agent the comparator Challenge/Solution layout. The three should
be merged into one new `TRUST.md` before release.

Response to `APPROVALS/reviews/trust.opus.md` and `trust.fable.md`: the in-band checks in
`EGCheck/Final.lean` (`type_of%`, `#guard_msgs` on `#print axioms`, the `run_cmd` comparison) can be
spoofed by any imported untrusted module and are therefore a **developer convenience, not the
acceptance criterion**. The criterion must be out-of-band.

## 3. Replace "How to check" with an OUT-OF-BAND acceptance criterion

A release is accepted only if ALL of the following pass, in a **fresh clone with no restored `.lake`
caches**, with formal-conjectures built from the pinned source before any project code is compiled:

1. `./scripts/check_pins.sh` (pins, toolchain commit, clean package worktrees — tooling agent).
2. `lake env lean --run scripts/FinalCheck.lean` exits 0. It uses `importModules` (`loadExts :=
   false`, so **no project elaborator, macro, delaborator or initializer runs**) on
   `#[FormalConjectures.ErdosProblems.«184», EGCheck.Final, EG, EGCheck]` and checks, all by literal
   `Name`:
   * provenance/module origin of `Erdos184.erdos_184`, `Erdos184.IsCycleOrEdge` (from
     `…ErdosProblems.«184»`), `SimpleGraph.IsDecomposition` (from `…SimpleGraph.Decomposition`) and
     `EGCheck.erdos_184` (from `EGCheck.Final`); no project module re-declares a package constant;
   * an import that would clash on a duplicate `Erdos184.erdos_184` (defeats a fake upstream);
   * both theorems are `.thmInfo`, both upstream definitions `.defnInfo`;
   * strict `Expr.equal` (binder names and annotations included) of the two statement types after
     renaming universe parameters by position;
   * `collectAxioms EGCheck.erdos_184` is exactly `{propext, Classical.choice, Quot.sound}`
     (`sorryAx` reported separately; a failure unless `--allow-sorry`), by an independent traversal
     cross-checked against Lean's `collectAxioms`;
   * a **kernel replay** of every project constant (renamed, on top of the imported package
     environment) — catches `debug.skipKernelTC`/`addDecl` bypasses that leave a valid-looking
     `.olean`;
   * the `EG`/`EGCheck` axiom+attribute policy (`scripts/Axioms.lean` with `--no-sorry`): no axiom
     outside the three, no `axiom`/`unsafe`/`partial`/`@[extern]`/`@[implemented_by]`/`@[init]`;
   * a meta-type scan (no project constant's type mentions `Lean.Elab`/`Macro`/`Parser`/`IO`/… —
     the project is pure mathematics, so such a constant is an elaborator/macro/initializer hook);
   * `statement-sha256` / `closure-sha256` / `lean-githash` equal the pins above.
3. `lake env leanchecker --fresh EGCheck.Final` (bundled with the toolchain; independent kernel
   replay of the whole environment). Measured ~21 min, ~10 GB RSS: use a ≥ 16 GB runner.
4. `leanprover/comparator` with a `Challenge.lean` CI verifies byte-identical to the pinned
   `184.lean`, `theorem_names = ["Erdos184.erdos_184"]`, `permitted_axioms` = the three (bridge
   agent's Challenge/Solution layout; see `formal/work/trust/bridge.md`).

The in-band `#guard_msgs` and `run_cmd` in `EGCheck/Final.lean` are explicitly **advisory** (a fast
first line for developers); they are not evidence, because imported modules can redefine `type_of%`,
`run_cmd`, `#print axioms` and `#guard_msgs`, or skip the kernel.

### What FinalCheck establishes and does not

* Establishes (given the pinned toolchain and package `.olean`s): the statement of
  `EGCheck.erdos_184` is exactly the pinned upstream statement; it depends only on the three axioms;
  every project constant is kernel-valid and free of the forbidden constructs.
* Does **not** establish that the package `.olean`s were compiled from the pinned sources (that is
  `leanchecker --fresh`, the from-source Challenge build, and check_pins' clean-worktree check), and
  it loads untrusted `.olean`s into its own process (a crafted loader-exploit `.olean` is out of
  scope; comparator's sandboxed build covers it). Hence checks 3 and 4 are also required.
