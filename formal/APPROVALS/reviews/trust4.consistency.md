## 2. Mismatches and overstatements (fix before applying)

**M1 (factual error; the reader's recipe fails on the honest tree).** §2 item 7a says the gate
rejects "Python files outside `formal/scripts/`"; §4.2 tells the reader to confirm that
`git ls-files` at `R` contains "no `*.py` outside `formal/scripts/`"; §4.5 step 1 says "no `*.py`
file is tracked outside `formal/scripts/`". The repository tracks ten Python files under `code/`
(`code/apply_patch.py`, `code/e2e/e2e_sim.py`, `code/extremal_search.py`, …), and the gate

l. 415–418) and `formal_zone()` rejects `.py` only inside `formal/` (l. 458); the gate's own header
says exactly that ("any `.py` in formal/ outside formal/scripts/ … `*.py` at the repository
root"). The `--dev` run above passes with these files present. Harmless for the trust argument
(the snapshot contains only `formal/`, `.github/`, `.claude/`, and Python runs with `-I`), but
the three sentences are wrong and the §4.2/§4.5 checks as written would reject the honest release
commit. Fix: "no `*.py` in `formal/` outside `formal/scripts/` and none at the repository root".

**M2 (describes the staged file, not the committed one).** §1 says `EGCheck.erdos_184` is "of type
`type_of% @_root_.Erdos184.erdos_184.{u}` (the upstream module is imported first and directly)",

deny column, which is already labelled correctly.)
